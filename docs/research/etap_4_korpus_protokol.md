# Етап 4. Корпус для дослідження шифрів

Точний спосіб отримання, версії сторінок, розміри й хеші в `raw/acquisition.json`.

### Походження та використання

Project Gutenberg позначає роман Остін як public domain **у США**; його умови окремо радять читачам поза США враховувати місцеве право. Видання Діккенса на Вікіджерелах, як і видання Нечуя-Левицького, позначене суспільним надбанням у світі. Основні твори авторів XIX—початку XX ст. перебувають поза строком життя плюс 70 років; окремо враховуємо права на цифрові внески. Леся Українка померла 1913 року. Внески й оболонка Вікіджерел мають окремі умови Creative Commons Attribution/Share-Alike. Це обґрунтовує **використання текстів у дослідженні**, але перед окремим поширенням повних електронних копій варто перевірити умови конкретного файлу, цифрової редакції та атрибуції.

Сторінки джерел і права: [Gutenberg terms](https://www.gutenberg.org/policy/terms_of_use.html), [A Christmas Carol](https://en.wikisource.org/wiki/A_Christmas_Carol_(Dickens,_1843)), [Кайдашева сімя̀](https://uk.wikisource.org/wiki/Кайдашева_сімя̀), [Лісова пісня](https://uk.wikisource.org/wiki/Лісова_пісня), [Закон України про авторське право, ст. 31](https://data.rada.gov.ua/ogd/zak/perv/text/d521966.htm). Це пояснення меж використання корпусу, а не повний правовий висновок про всі можливі видання.

## 2. Як відтворити корпус

Файли вже включено до збірки. Замість прямого завантаження TXT зафіксовано видимий повний текст сторінок: Gutenberg `pre.textContent`; Вікіджерела `innerText` основного блоку без заголовків сайту. Для складених творів частини з’єднано у порядку видання; точні URL та `oldid` кожної частини — у журналах `raw/en_dickens_parts.json` і `raw/uk_nechui_chapters.json`. Хеші в `raw/acquisition.json` належать саме збереженим UTF-8-знімкам. Заново отримані з вебсайтів сторінки можуть змінитися, тому для точного повторення користуйтеся файлами збірки.

У каталозі розпакованої збірки виконайте:

```sh
python build_corpus.py selftest
python build_corpus.py build
```

Потрібен Python 3.11+; зовнішніх бібліотек немає. Маніфест записує SHA-256 кожного вхідного та похідного файла, версії Python/Unicode й хеш скрипту. `raw/` скрипт не змінює.

## 3. Правила перетворення

| Потік | Правило | Одиниця аналізу |
|---|---|---|
| Зафіксований текст `raw/` | Не змінюється; SHA-256 береться з точних байтів збереженого UTF-8-знімка. | Байт файла. |
| `text_utf8.txt` | UTF-8 strict, можливий BOM забирається; Gutenberg ліцензійна обкладинка відсікається за точними START/END маркерами; для Вікіджерел збережений текст береться як є; CRLF/CR → LF; Unicode NFC. Регістр, пробіли, пунктуація і цифри залишаються. | Unicode code point; кількість байтів рахується окремо. |
| `letters.txt` | З попереднього файлу кожний символ переводиться у верхній регістр, після чого лишається **лише** символ з оголошеної абетки. Українська — 33 знаки `АБВГҐДЕЄЖЗИІЇЙКЛМНОПРСТУФХЦЧШЩЬЮЯ`; латинська — 26 `A…Z`. Пробіли і знаки не просувають позицію ключа для базової класичної конфігурації. `Ґ`, `Є`, `І`, `Ї` залишаються самостійними; `Ь` — самостійна позиція. | Літера **обраної** абетки. |
| `utf8_at_most_N.bin` | Початок `text_utf8.txt` не більший за N байтів, обрізання **на межі Unicode code point**, щоб UTF-8 лишався правильним. У маніфесті — фактична кількість байтів. | Байт; бюджет може відрізнятися від фактичної довжини на 1–3 байти. |
| `letters_N_{head,middle,tail}.txt` | Три вікна по N літер із початку, середини й кінця *того самого* перетвореного тексту; фактичний зсув записаний у маніфесті. | Літера; підвибірки того самого твору не є незалежними творами. |
| `controls/` | Чотири окремі сконструйовані контролі: нулі, повторення ASCII A, послідовність 0…255, змішані українська+англійська з цифрами. | Байт; **не** природна мова. |

Алфавіти зафіксовані тут як наші експериментальні угоди, це не «стандартний алфавіт для кожного історичного шифру». Код **не** здійснює транслітерації історичного правопису, не вгадує відсутні букви й не змінює `ё/ѣ/ъ` на сучасні. `outside_alphabet_letters` і приклади таких символів видно в маніфесті. Стару орфографію аналізувати разом із цим обмеженням; за потреби окремий варіант з явним відображенням літер створювати під новим ID.

## 4. План вибірок і порівняння

- Основне зіставлення **класичних** шифрів: для кожної відповідної мови однакові `letters.txt`, вікна 16/32/256/4096/16384 літер та повний очищений текст. Для шифрів із групуванням відзначати правило доповнення й довжину виходу; для Playfair, Hill, решітки й гомофонної заміни перед запуском записати ще їхній точний профіль вводу.
- Основне зіставлення **байтових** шифрів: однакові байтові файли `text_utf8.txt`, короткі бюджети 0/1/15/16/17/31/32/33/256, середній 4096, довгий 65536 і повний текст. Вимірювати фактичні байти; AES-режими не «переводять букви в номери». Не всі асиметричні схеми можуть прямо обробляти ці повідомлення — для них знадобиться визначений протокол/окрема задача.
- Контроль впливу змісту: природний текст, повтори й змішані дані зберігати окремими серіями. Шифротекст з випадковим нонсом не порівнювати побайтно між різними запусками без фіксації параметрів.
- Графіки частот мають бути підписані «літери з `letters.txt`» або «байти з `text_utf8.txt`». Байти UTF-8, Unicode code points і графемні кластери — різні речі; ця збірка **не** вміє рахувати графеми і не заявляє такого результату.
- Фінальна наукова стаття цитує оригінальний твір, саме цифрове видання і дату доступу; таблиці результатів несуть ID, SHA-256 входу, назву перетворення, його кодову версію, зсув вікна і параметри шифру.
