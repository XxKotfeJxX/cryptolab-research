# SHA-256 — спільний примітив

Стандарт: NIST FIPS 180-4 (2015), розділи 4.1.2, 4.2.2, 5.1.1, 5.2.1, 5.3.3 і 6.2.2: https://nvlpubs.nist.gov/nistpubs/fips/nist.fips.180-4.pdf .

Профіль: байтовий вхід будь-якого вмісту; довжина в бітах менша за 2^64. Слова і довжина записуються старшим байтом уперед. Доповнення: біт 1, нульові біти до 448 modulo 512, потім 64-бітна довжина в бітах. Результат — 32 байти у порядку H0…H7. Перші 8 квадратних коренів простих чисел задають початковий стан; кубічні корені перших 64 простих чисел задають константи раундів. Власний код обчислює їх під час першого виклику цілочисельним пошуком, без залежності від округлення `sqrt`/`cbrt`, і звіряє **всі 8 та 64 слова** з опублікованими таблицями FIPS 180-4, §§5.3.3 і 4.2.2.

Опубліковані точні вектори: NIST, *Secure Hash Algorithm — Message Digest Length = 256*, приклади «One Block Message Sample» (`abc`) і «Two Block Message Sample» (`abcdbc…nopq`): https://csrc.nist.gov/csrc/media/projects/cryptographic-standards-and-guidelines/documents/examples/sha256.pdf . Тести порівнюють повний digest. Окремо перевіряються порожній вхід, межа доповнення 55/56/64 байти і довший вхід незалежним Python 3.14 `hashlib` через `tests/reference/python_oracles.py`; точні байтові входи в `tests/test_cli.py`.

Цей модуль потрібний для майбутнього RSA-OAEP. Маніфест етапу 4 перевіряється окремим інструментальним скриптом `scripts/corpus_stage4.py` із Python `hashlib`; це не частина власного криптографічного ядра. Власний SHA-256 не замінює перевірку походження самого маніфесту.
