# Байтовий одноразовий блокнот — позиція №23, картка №18

Версія 0.1. Навчальний профіль: `otp xor --in FILE --key-file FILE --out FILE`. Вхід і ключ — довільні байти, не UTF-8-рядки; вихід має ту саму довжину. Для кожного індексу `c[i] = p[i] XOR k[i]`; зворотна операція тотожна. Ключ повинен мати **рівно** стільки байтів, скільки вхід, включно з нульовою довжиною. Жодного повтору, обрізання чи генерування ключа немає.

Ця операція є справжнім OTP лише за умови, що ключ рівномірно випадковий, незалежний, таємний і ніколи не використовується повторно. CLI не може довести ці умови й не керує життєвим циклом ключа. Для тесту допускається публічна фіксована пара; її не можна вважати секретним ключем. Значення ключа не потрапляє в журнал або SVG. Помилки довжини чи збігу шляхів відхиляються до запису виходу.

Джерело теоретичної умови: [Claude Shannon, *Communication Theory of Secrecy Systems*, 1949](https://onlinelibrary.wiley.com/doi/10.1002/j.1538-7305.1949.tb00928.x), DOI 10.1002/j.1538-7305.1949.tb00928.x. Для байтової операції перевірка — незалежний Python `bytes(a ^ b for a,b in zip(...))` на фіксованих байтах, порожньому вході та граничних значеннях; це не перевіряє випадковості ключа.
